# 过程卡片（timeline-cards）

CC GUI（ccgui-next）Tier-1 JS 插件。接管会话时间线里那张 **「思考 N 次 工具调用 M 次 >」** 的折叠行，
把它渲染成一张 **任务摘要卡**：

```
┌─ ✦ 任务摘要  [进行中]        读取文件 application.yml   4/4  ⌄ ─┐
│  执行日志                                          4/4 步       │
│  ✓ 读取文件   application.yml          D:/work/.../resources    │
│  ✓ 读取文件   application-dev.yml                              │
│  ✓ 读取文件   JeecgSystemApplication.java                       │
│  ✓ 读取文件   package.json                          [参数]      │
│  ◌ 执行命令   编译后端                                        │
└────────────────────────────────────────────────────────────────┘
```

## 它解决什么

宿主默认把「思考 + 工具调用」折成一行纯文字（`思考 16 次 工具调用 31 次 >`），展开后是
按时间平铺的原始列表——要读懂这一轮在干什么，得自己把 `Bash`、`Read file.ts:301-591:raw`
这类原始标签翻译成人话。本插件把这一步替你做掉：

- **动词语义化**：`Bash` → 执行命令、`Read` → 读取文件、`Edit` → 编辑文件（带 `+N -M`）、
  `Grep` → 搜索、`WebFetch` → 抓取网页、`TodoWrite` → 更新任务清单……
- **主/次信息分层**：主文本是文件名、命令描述或命令首行；次要文本是目录、原始命令，等宽小字。
- **状态与计数**：进行中 / 已完成 / 出错（`is_error`、`stderr`）三态；头部显示完成步数。
- **参数按需展开**：每步的 `args` / `result` 原始 JSON 或 stdout/stderr 收起，点「参数」才看。
- **思考段落**：大脑图标 + 左轨道灰文，默认只露首行，点击展开全文。

## 实现方式（为什么不用 DOM 注入）

宿主 `MessageTimeline` 在渲染每一行前先查 `timelineRowRegistry`，
插件注册的 renderer 优先于内置的 `kind` 分支（`src/features/chat/components/MessageTimeline.tsx`，
v1.0.6 起就有这个扩展点）。因此本插件只注册 `kind: "process"`，不改宿主、不注入 DOM、
不读内部 store，宿主升级不会因为类名变化而碎掉。样式走安装期自动注入的 `styles.css`
（宿主包进 `@layer ccgui-plugins`），不需要 `theme` 权限。

## 接管的代价与补位

注册 `kind="process"` 会绕过宿主原本的三件事，插件用设置项补位：

| 宿主原能力 | 插件替代 |
|---|---|
| 最新一组自动展开、思考结束自动折叠 | 有 live 思考 ⇒ 展开；思考结束 ⇒ 按「思考结束后自动折叠」收起；用户手点过就听用户的 |
| 设置 → 通用 → 「思考自动折叠」 | 设置页同名开关 |
| Ctrl+F 命中折叠区时自动展开并高亮 | **未覆盖**（已知限制）：搜索计数与行跳转仍由宿主数据层完成，只是不会替你展开卡片 |

## 设置项（设置 → 插件 → 过程卡片）

| 项 | 默认 | 说明 |
|---|---|---|
| 思考结束后自动折叠 | 开 | 关掉后这一轮结束前保持展开 |
| 最新一组默认展开 | 开 | 时间线最后一张卡默认展开 |
| 显示思考内容 | 开 | 关掉后只保留工具调用步骤 |
| 使用语义化动词 | 开 | 关掉后显示原始工具名 |
| 每页步数 | 40 | 超过该数量的步骤分页（5–200） |

配置存在宿主 KV（`ctx.storage`），随插件卸载保留。

## 开发与验证

```bash
node --test test.mjs      # 分类器 / 结果格式化 / 卡片数据装配（17 条用例）
```

安装：CC GUI → 设置 → 插件 → **从本地目录安装** → 选中本目录（含 `manifest.json` 这一层）。
改完 `main.js` / `styles.css` 后重新走一遍安装即可热重载（同 id 覆盖），无需重启。

## 「进行中」是怎么判断的

宿主的 `turnLive` 只传给**内置**渲染器，插件 renderer 只收到 `{ row }`；工具行本身也不带
`live` 标记（宿主在工具一落地就用 `settleLiveRows` 把整段思考的 live 清掉了）。所以插件
从时间线结构里读信号：

- 流式输出期间，宿主会在时间线末尾多挂一条「思考中…」状态条
  （`AgentThinking`，`role="status"`），`streaming` 一结束就摘掉；
- 插件用 `MutationObserver` 盯 `[data-index]` 容器列表，**末尾挂着状态条 = 本轮仍在执行**；
- 只有末条内容行才会显示「进行中」，往上的历史卡片一律「已完成」。

判定「那一行是末条内容行」还要同时满足「它是已挂载行里 index 最大的」和「滚动容器已到底」，
避免虚拟列表把滚出去的历史行当成末尾。

## 已知限制

- 多步长任务默认分页 40 条/页；翻页状态不跨卡片记忆。
- 「进行中」依赖宿主尾部的流式状态条（`role="status"` + `[data-index]` 结构）。宿主若改变
  这段 DOM，插件会退化成「一律已完成」——不会误标运行中，但会少报。
- 卡片不参与宿主的时间线搜索高亮（见上表）。
