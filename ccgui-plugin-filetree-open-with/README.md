# 文件树 · 在关联应用中打开（filetree-open-with）

CC GUI（ccgui-next）Tier-1 JS 插件：在右侧文件树右键菜单里追加一行 **「在关联应用中打开」**，
点击后交给系统默认关联程序打开选中的文件或文件夹（Windows 下相当于资源管理器里双击）。

## 为什么要 DOM 注入

宿主 SDK 只提供了 `sessionMenu` / `addMenu` / `panelTab` 这类注册表，**没有任何文件树/资源管理器
右键菜单的扩展点**。所以本插件在菜单弹出时通过 `MutationObserver` 找到它，往里面插一行。

## 怎么认出「这是文件树菜单」

用菜单里的一对固定项做指纹：同时存在「新建文件」**和**「新建文件夹」的 `role="menu"`，才认定为文件树
菜单；其他菜单不碰。插入位置取菜单里第一条 `<hr>` 之前，即「在资源管理器中显示」之后、「移到废纸篓」之前。

选中的路径来自菜单自身的 `aria-label`。已经注入过的菜单会跳过（幂等）。

## 为什么用 `plugin_exec_spawn` 而不是 `exec_run`

`exec_run` 把命令及其孙进程放进 kill-on-close 的 Job 对象——`cmd /c start` 一退出，宿主就把刚打开的
应用一起杀掉。`plugin_exec_spawn` 的 detached 路径不建 Job、直接丢句柄，进程能存活。

## 设置页

设置 → 插件 → **文件树 · 关联打开**：一个总开关，关掉会立刻移除已注入的行，不需要卸载插件。

## 已知边界

- 只对**已经弹出来的**菜单生效；菜单关闭状态不做任何注入。
- 依赖宿主菜单的文案与结构（`新建文件` / `新建文件夹`、`role="menuitem"`、首个 `<hr>`）。宿主改版可能失效。
- 非 Windows 平台上 `cmd /c start` 不存在——目前只按 Windows 实现。

## 权限

| 权限 | 用途 |
|---|---|
| `exec:cmd` | 调 `cmd /c start "" "<path>"` 打开文件 |
| `storage` | 记住开关状态 |
| `ui:settings-section` | 设置页里的总开关 |

## 安装 / 更新 / 卸载

- **安装**：CC GUI → 设置 → 插件 → 「从本地目录安装」→ 选中本目录（含 `manifest.json` 这一层）。
- **更新**：覆盖 `main.js` 后重新走一遍「从本地目录安装」即可热重载。
- **卸载**：插件页该行点卸载。
